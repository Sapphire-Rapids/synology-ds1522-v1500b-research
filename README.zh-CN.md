# Synology DS1522+ / V1500B 研究

[English](README.md)

本项目研究一台 DS1522+ 从 Ryzen Embedded R1600 更换为 V1500B 后无法完成启动的原因。

**目前只有离线候选修改，尚未验证升级成功，也没有可直接刷写的镜像。**

固件已经包含可执行的 V1500B 处理逻辑。当前最有力的假设是：CPU 分类选择了不适合 DS1522+ 主板的 PCIe 布局。缺少失败时的 V1500B 启动记录，因此这条路径仍未证实。

- 候选修改改变 **130 字节的拓扑与时钟表数据**。八组人工构造的选择器输入通过检查：两个 CPUID 输入 × 四个 SMU 高位取值。这不验证真实 PCIe 链路训练。
- 与官方采用 V1500B 的 DS1525+ 比较，家族／封装检查代码、八个 PMU 固件条目及相关表解释代码相同；完整固件栈仍有差异。
- **RS1221+ 已提供同 CPU 的拆分先例：**其官方 V1500B 固件将逻辑 lane 0、1 分别配置为 x1。DS1522+ 的完整组合和最终端口映射仍未验证。[机型对照](evidence/same_cpu_reference/summary.json)
- 修改会使厂商更新签名失效。修改后的原始镜像能否被启动链接受，仍未确定。

请先阅读[技术发现](docs/findings.md)和[复现说明](docs/reproduce.md)。目前不建议再次换芯，应先验证部署、恢复和启动诊断方式。

公开内容包括分析、来源与复现脚本，不包含专有固件二进制或机器专属采集数据。官方固件下载来源和输入哈希见 [sources.json](sources.json)。
